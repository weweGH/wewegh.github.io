# 프로젝트 회고

> 해당 문서는 프로젝트 종료 후 '회고'를 기록합니다. 중단된 프로젝트도 포함. 다음 양식으로 정리

1. 상황 (Context) `우리는 지금 어떤 현실에 있었는가?`
    - 문제의 배경
    - 누가, 언제, 어떤 불편/제약 속에 있었는지
    - 아직 판단이나 해석 X
    - [주의] 문제 원인 설명까지 같이 하지 말 것
    - [주의] 이미 해결책 힌트가 들어감

2. 왜 이게 중요한 문제였는지 (Decision) `그래서 이 문제가 왜 '판단이 필요한 문제'였는가?`
    - 비즈니스/조직 관점
    - 조직의 선택, 속도, 리스크
    - [주의] context를 다시 말함
    - [주의] '불편했다', '어려웠다' 수준에서 끝남

3. 내가 정의한 질문 (Framing) `주어진 문제를 그대로 풀지 않고, '진짜 풀어야 할 질문'을 다시 정의했는가?`
    - 해결책이 열려있는. 판단 기준이 바뀔 수 있는 질문
    - [주의] 어떤 모델을 사용할까? X
    - [주의] 어떤 지표를 확인할까? X

4. 분석 및 인사이트 (Insight) `그래서 데이터를 통해 무엇을 알게 되었는가`
    - 데이터 분석 결과
    - 숫자보다 패턴
    - "그래서 뭐가 보였는지"
    - [주의] 행동만 나열('로그분석함', '모델 실행')

5. 그래서 어떤 판단이 내려졌는지 (Outcome) `그래서 실제로 어떤 선택이 내려졌는가`
    - 결과가 '분석 결과'로 끝남
    - "왜 그 선택이었는지"가 보임
    - [주의] 기술만 말함


6. 그 경험이 나에게 남긴 관점 (Learning) `이 경험이 내 사고를 어떻게 바꿨는가?`
    - 경험을 축적된 관점으로 전환
    - 나의 판단 기준 변화
    - 다음 문제에도 적용 가능
    - [주의] 교훈이 너무 일반적
    - [주의] 기술적인 배움만 언급

## 원료 첨부파일 검색 RAG | 2025.4.9 ~ 2025.11.21

1. CONTEXT
    - 연구원, 규제 체크 담당자들이 성분에 대한 검색이 필요할 때, 모든 PDF를 일일이 열어서 확인해야 함

2. DECISION
    - 연구원과 규제 담당자의 검색 비용 증가는 단순한 불편을 넘어, 의사결정 지연과 중복 검토로 이어지고 있었으며, 이는 R&D 생산성과 규제 대응 속도에 직접적인 영향을 주는 문제였다.

3. FRAMING
    - 사용자들은 정확한 문서를 찾고 싶은 것인가, 아니면 의사결정에 필요한 핵심 맥락을 빠르게 얻고 싶은 것인가?

4. INSIGHT
    - 특정 팀의 검색 로그와 문서 열람 패턴을 분석한 결과, 사용자는 정확한 문서 자체보다 성분 관련 요약 정보와 규제 맥락을 빠르게 파악하는 데 더 많은 시간을 쓰고 있음을 확인했다.

5. OUTCOME
    - 따라서 단순 키워드 검색 개선이 아니라, 의사결정에 필요한 정보를 요약·맥락화하는 방향이 더 적절하다고 판단했고, 이를 위해 시멘틱 서치 기반의 RAG 접근을 선택했다.

6. LEARNING
    - 이 경험을 통해, 검색 문제에서 중요한 것은 항상 기술적 성능이 아니라 사용자가 어떤 결정을 하기 위해 검색하고 있는지를 이해하는 것이라는 관점을 갖게 되었다.

## 제품 유사도 탐색 PoC

1. CONTEXT
    - 연구원이 제품을 개발할 때, '타겟 제품'에서 시작하는 경우가 종종 있음
    - 고객사에서 의뢰를 할 때, '타겟 제품'을 기준으로 사용감을 개선하거나 컬러를 개선하는 경우가 있음
    - 이 경우에 연구원은 '타겟 제품'에 대한 분석을 위해 유사 제품을 탐색함
    - rev) 연구원들은 제품 개발 초기 단계에서 종종 특정 ‘타겟 제품’을 기준점으로 삼아, 시장 내 유사 제품을 파악한 뒤 방향을 설정하는 방식으로 업무를 시작하고 있었다.

2. DECISION
    - '유사 제품'을 찾기 위한 서비스가 현재 없음. '유사 제품'을 찾으려면, 연구원 개인이 일일이 분석해야 함
    - rev) 하지만 유사 제품을 체계적으로 탐색할 수 있는 도구가 없어, 각 연구원이 개인적으로 성분표를 비교하며 분석해야 했고, 이로 인해 초기 기획 단계에서 많은 시간과 노력이 소모되고 있었다. 따라서 유사 제품 탐색을 구조적으로 지원할 필요가 있는 상황이었다.

3. FRAMING
    - 성분의 존재 유무로 판단한 유사도가 의미있을까? 
    - rev) 이때 문제를 단순히 “얼마나 정교한 유사도를 만들 것인가”가 아니라, **“개발 초기 의사결정 단계에서, 성분의 존재 유무만으로도 의미 있는 기준을 제공할 수 있는가?”**라는 질문으로 재정의했다.

4. INSIGHT
    - 일부 데이터로 로직 테스트한 결과, 직관적으로 비슷한 제품을 탐색함.
    - 유저 인터뷰 결과, '타겟팅' 시점에서 업무 효율성 증진에 도움이 될 것 같다고 의견을 받음
    - rev) 일부 샘플 데이터를 활용해 성분 존재 유무 기반 유사도 로직을 테스트한 결과, 연구원들이 직관적으로 유사하다고 인식하는 제품들이 상위에 노출되는 경향을 확인했다. 또한 사용자 인터뷰를 통해, 이와 같은 결과가 특히 ‘타겟 제품을 기준으로 방향을 잡는 초기 단계’에서 업무 효율을 높이는 데 도움이 될 수 있다는 피드백을 얻었다.

5. OUTCOME
    - PoC이므로 데이터셋은 '립틴트'로 제한하여 서비스 오픈
    - 이 PoC의 목적은 연구원에게 '이런 것도 할 수 있구나!'라는 생각이 들게 하는 것이 목표
    - 따라서, 가장 단순한 상세페이지 전성분 데이터를 활용하여 TF-IDF cosine 유사도로 유사 제품 5개를 조회할 수 있도록 함
    - rev) 이에 따라 PoC 단계에서는 범위를 ‘립틴트’ 카테고리로 제한하고, 가장 단순한 형태의 전성분 데이터만을 활용해 TF-IDF 기반 cosine 유사도로 유사 제품 Top 5를 제공하는 서비스를 구현했다. 이 PoC의 핵심 목적은 모델의 완성도가 아니라, 연구원에게 “이런 방식의 탐색도 가능하다”는 새로운 판단 기준을 제시하는 것이었다.

6. LEARNING
    - 결과적으로, 연구원에게 중요한 것은 '함량'. '전성분 유무'만으로 유사한 제품을 탐색하는 것은 아직 부족함
    - rev) 이 과정을 통해, 연구원들이 궁극적으로 중요하게 여기는 요소는 단순한 성분의 존재 여부가 아니라 ‘함량’이라는 점을 명확히 인식하게 되었고, 성분 유무 기반 유사도는 초기 방향 설정에는 유효하지만 보다 정교한 판단을 위해서는 다음 단계의 확장이 필요하다는 관점을 갖게 되었다.
